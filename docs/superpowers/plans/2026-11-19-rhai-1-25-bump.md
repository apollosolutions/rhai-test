# Rhai 1.25 Bump (Router v2.19.1 parity) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring rhai-test from Rhai 1.23.6 / Router v2.12.0 to Rhai ~1.25 / Router v2.19.1 so scripts validated by rhai-test behave like they do in Router v2.18.0+.

**Architecture:** rhai-test depends on a fork of the Router (`apollosolutions/router`) that only widens visibility of Rhai plugin internals and adds two test-harness helpers (AS-389). The bump has two parts: rebase those fork commits onto upstream `v2.19.1` as a new branch, then point rhai-test's `apollo-router` git `rev` at that branch and raise the `rhai` requirement to match. Cargo must resolve exactly one `rhai` crate, because rhai-test passes its own `rhai::Engine` into the Router's registration functions.

**Tech Stack:** Rust 2021, `rhai` crate, `apollo-router` (git dependency on fork), knope (releases), GitHub Actions.

**Spec:** [TSH-27618](https://apollographql.atlassian.net/browse/TSH-27618), "Update rhai-test to Rhai 1.25 to match Apollo Router v2.18.0+". Related: AS-384 (the previous bump, commit `c3a19d1`), AS-389 (mock additions, `0e6baa4`), TSH-27510 (customer origin).

## Facts established while planning

- Upstream Router `apollo-router/Cargo.toml`: `v2.12.0` and `v2.17.0` → `rhai ~1.23.6`; `v2.18.0` and `v2.19.1` → `rhai = { version = "~1.25.0", features = ["sync", "serde", "internals"] }` (router PR #9527). Its `[dev-dependencies]` still lists `rhai 1.23.6`, which does not affect dependents.
- Latest stable Router is `v2.19.1` (2026-11-16). The customer is upgrading to 2.19.1.
- Latest Rhai 1.25 patch is `1.25.1`. It restores `rhai::plugin` exports that `1.25.0` removed. rhai-test uses `use rhai::{plugin::*, ...}` in `src/extensions/apollo.rs:11`.
- Fork branch `feature/rhaitest-v2.12.0` is 18 commits ahead of `v2.12.0`, with HEAD at merge `3e1132a996014abbe2c040185a130dc9cce0b948`. It touches `lib.rs`, `plugins/mod.rs`, `plugins/rhai/{mod,router,subgraph,supergraph,execution}.rs`, `plugins/rhai/engine/{mod,types}.rs`, `plugins/rhai/engine/registration/mod.rs`, `context/mod.rs` and `services/subgraph.rs`, plus `README.md` and `.github/workflows/test.yml`.
- Upstream commits since v2.12.0 that touch the same files, and so are likely to conflict: `80073f34` (#9675, explicit rhai imports), `0200ab30` (#9527, the rhai bump), `753be305` (#10004, stop disclosing Rhai errors to clients), `7e86637b` (#9070, `intern_strings`), `617eaa79` (#9072, rhai duration metric), `e7b5b0cb` (context), `e294afc7`/`6f2dfa4c`/`309ff86d`/`68198919` (subgraph service) and `500cd6cc` (lib.rs).
- Both of rhai-test's error matches (`src/engine/error_handling.rs`, `EvalAltResult` and `ParseErrorType`) have catch-all arms, so new Rhai variants still compile.

## Global Constraints

- Router base tag: `v2.19.1`. New fork branch name: `feature/rhaitest-v2.19.1`. Do not modify or delete `feature/rhaitest-v2.12.0`, because released rhai-test 0.3.x builds pin it.
- rhai-test `rhai` requirement: `{ version = "~1.25.1", features = ["metadata"] }`. This is compatible with Router's `~1.25.0` and excludes 1.25.0, which lacks the plugin exports.
- `apollo-router` stays pinned by `rev = "<full sha>"`, not `branch`, matching the convention set in AS-389.
- The fork makes visibility changes and the AS-389 additions only, with no other behavior changes. Its README "What this fork does NOT do" still holds.
- Rust toolchain: stable rustc at least the version in upstream `v2.19.1`'s `rust-toolchain.toml` (`1.99.0`).
- Release type: `feat!` with a `BREAKING CHANGE:` footer, the same pattern as 0.3.0, so knope cuts **0.4.0**.

## Review Focus

1. **Duplicate `rhai` in the graph.** If two `rhai` versions resolve, rhai-test's `Engine` and Router's `Engine` are different types. Expect exactly one `rhai v1.25.x` in `cargo tree -i rhai`. (Task 2, Step 6.)
2. **Router helper errors after #10004.** `json::decode` on invalid input must still raise a catchable error inside a test, not panic or come back silently empty. (Task 2, test `Router json::decode error is catchable`.)
3. **Coverage mode.** `"coverage": true` instruments the source with regex before compiling. Rhai 1.24's optimizer changes (if-merge, constant map access) must not break the instrumented scripts. (Task 2, Step 7.)
4. **Stack-trace output for failing tests.** Customers read this text in CI. A deliberately failing test must still print file, line and message the way 0.3.1 does. (Task 2, Step 8.)
5. **AS-389 surface survives the rebase.** `context.remove` and writable `subgraph_request_id` still work. `examples/subgraph_request_id_correlation.test.rhai` and the existing context tests cover this and must pass unchanged. (Task 2, Step 5.)

- [ ] **Step 1: Write the failing version-proof test** in `examples/rhai-1-25-features.test.rhai`

Use the same header-comment style as `examples/rhai-engine-functions.test.rhai`. Each test below uses behavior that is new in 1.24 or 1.25, so on 1.23.6 the test errors:

```rhai
test("Rhai 1.24: arrays support sort_desc", ||{
    let a = [3, 1, 2];
    a.sort_desc();
    expect(a[0]).to_be(3);
    expect(a[2]).to_be(1);
});

test("Rhai 1.25: split is callable on a const string", ||{
    const CSV = "a,b,c";
    let parts = CSV.split(",");
    expect(parts.len()).to_be(3);
});

test("Rhai 1.25: index_of falls back to value comparison for strings", ||{
    let a = ["x", "y", "z"];
    expect(a.index_of("y")).to_be(1);
});

test("Rhai 1.25: \\${...} escapes interpolation in multi-line strings", ||{
    let s = `price: \${amount}`;
    expect(s).to_be("price: ${amount}");
});

test("Router json::decode error is catchable", ||{
    let caught = false;
    try { json::decode("{not json"); } catch { caught = true; }
    expect(caught).to_be(true);
});
```

- [ ] **Step 2: Run it on the current pins to confirm it fails**
